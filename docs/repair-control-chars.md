# 入力データの前処理（制御文字の修復）

LLMで生成した入力データに含まれる、壊れた制御文字を修復するスクリプト `src/scripts/repair_control_chars.py` の説明です。

## 問題

LLMで生成した入力では、`\u00e1` やLaTeXの `\beta` などに含まれるバックスラッシュがエスケープとして誤って解釈され、リストのセルの要素に制御文字が入り込むことがあります。Pythonの表記では `'Moro-Vel\x00e1zquez'` のように表示されます。

- NUL（U+0000）を含むファイルは、WEKOが `Internal server error` で読み込めません。
- それ以外の制御文字はWEKOが受け付けるため、壊れた値のまま公開されます。

このため、生成コマンドは制御文字を含む行をエラーにします。

## 使い方

```shell
uv run python src/scripts/repair_control_chars.py \
  --input path/to/input.tsv \
  --output path/to/input_repaired.tsv
```

PowerShellでは行末の `\` を `` ` `` に置き換えてください。

| 出力 | 内容 |
|---|---|
| `--output` | 修復した入力ファイル |
| `<出力名>_repairs.tsv` | 変更した要素の一覧。行番号、ID（`--id-column` の列の値、既定 `corpusid`）、列名、リスト内の位置、適用した規則、変更前（`repr` 表記）・変更後の値を並べる。出力先は `--report` で変更できる |
| `<出力名>_review.tsv` | 手作業で確認すべき要素の一覧（[下記](#手作業での確認が必要なもの)）。出力先は `--review` で変更できる |

出力先に同名のファイルがある場合は停止します。置き換えるときは `--overwrite` を指定してください。

## 修復の規則

リストのセルの文字列要素について、元の文字が1通りに決まる制御文字だけを元に戻し、元に戻せない制御文字は `\xNN` という4文字の文字列に置き換えます。

次の表では、制御文字そのものを `<U+0000>`、タブを `<TAB>` のように表記します。

| 規則 | 変換 | 例 |
|---|---|---|
| R1 | 制御文字（U+0000〜U+0006、U+000E〜U+001F）＋16進数2桁 → 制御文字の番号を上位、16進数2桁を下位とするコードポイントの文字（文字・結合文字・数字・記号になる場合のみ） | `Moro-Vel<U+0000>e1zquez` → `Moro-Velázquez` |
| R2 | U+0007・U+0008・U+000B・U+000C＋英字 → `\a`・`\b`・`\v`・`\f`＋英字 | `$<U+0008>eta$` → `$\beta$` |
| R3 | タブ＋既知のLaTeXコマンド名 → `\t`＋コマンド名、CR＋英字 → `\r`＋英字 | `Mu<TAB>ilde{n}oz` → `Mu\tilde{n}oz` |
| R4 | 上記に当てはまらない制御文字 → `\xNN` という文字列 | `$<U+0012>$` → `$\x12$` |

R3に当てはまらないタブ・改行（LF・CR）は変更しません。リストでないセルは修復の対象外です。

### 手作業での確認が必要なもの

LaTeXの `\nu` や `\nabla` などは、改行（LF）に変わっている可能性があります。しかし本物の改行と区別できないため、変更しません。改行の直後に既知のコマンド名が続く要素を `<出力名>_review.tsv` に書き出すので、手作業で確認してください。

## 修復後に生成し直すときの注意

修復したファイルの更新日時は、既定で元のファイルと同じにします（`--no-keep-mtime` で無効化）。生成されるZIPは入力ファイルの内容と更新日時で決まるため、元のZIPと同じ出力になるバージョンのツールで、同じ設定で生成し直すと、修復した行を含まないZIPは元のZIPと同じになり、[インポート台帳](register.md#インポート台帳)で登録済みとしてスキップされます。`--chunk-size` などの設定と台帳は、元のZIPを生成・登録したときと同じものを使ってください。

ただし現在の生成コマンドは、制御文字を含む行をエラーにします。そのため修復前のファイルから作ったZIPは、次のどちらかで生成されたものです。生成方法によって注意点が異なります。

> [!WARNING]
> **制御文字の検査が入る前のバージョン（commit 3139fbc より前）で生成した場合**: ZIPを同じ内容で再生成できるのは、commit 6e5cadd 以降のバージョンで生成したZIPだけです。UTCオフセット付きの日付を含む場合は、commit be8ce40 以降で生成したZIPに限られます。それより前のバージョンで生成したZIPは、修復した行を含まないものも新しいZIPと判定されるため、登録済みのZIPを登録対象から外してください。
>
> NUL以外の制御文字だけを含むZIPは、WEKOが受け付けるため登録済みの可能性があります。そのZIPは修復で内容が変わるため、台帳では未登録と判定され、重複登録されます。
>
> 修復一覧の行番号から該当するZIPを求め、登録済みのものは登録対象から外してください。`--chunk-size` を N とすると、該当するZIPは `(行番号 - 2) // N + 1` 番目です（`//` は小数点以下を切り捨てる割り算）。生成時に `--skip-invalid-rows` で除外した行がある場合は、この式は当てはまりません。

> [!WARNING]
> **`--skip-invalid-rows` で制御文字を含む行を除外して生成した場合**: 修復したファイル全体から生成し直さないでください。修復した行が戻ると、その行以降のZIPの区切りがすべてずれます。そのため最初の修復行を含むZIP以降はすべて新しいZIPと判定され、登録済みの行が重複登録されます。
>
> 除外した行を登録するには、`invalid_rows.tsv` をこのスクリプトで修復し、[除外した行の登録手順](generate.md#エラーのある行)に従ってください。
